# 生产部署速查

这份文档只记录上线最常用命令和关键检查点。当前推荐方案是：

```text
已有中间件 compose：MySQL / Redis / ONLYOFFICE / 中间件 Nginx
业务 compose：kop-backend / kop-frontend
```

`kop-frontend` 自带 Nginx，负责托管前端静态文件并把 `/api` 代理到 `kop-backend`。

## 1. 前置条件

服务器上应已经有这些中间件容器：

```bash
docker ps
```

确认存在：

```text
middleware-mysql
middleware-redis
middleware-onlyoffice
```

确认中间件网络存在：

```bash
docker network ls
```

默认网络名：

```text
shared-middleware_default
```

## 2. 生产配置

第一次部署时复制配置：

```bash
cp .env.prod.example .env.prod
```

编辑：

```bash
nano .env.prod
```

最少要确认这些值：

```env
FRONTEND_HTTP_PORT=80
BACKEND_HTTP_PORT=8000
VITE_API_BASE_URL=
MIDDLEWARE_DOCKER_NETWORK=shared-middleware_default

CORS_ORIGINS=http://服务器公网IP

MYSQL_HOST=middleware-mysql
MYSQL_PORT=3306
MYSQL_DATABASE=KOP
MYSQL_USER=root
MYSQL_PASSWORD=服务器真实 MySQL 密码

REDIS_HOST=middleware-redis
REDIS_PORT=6379
REDIS_PASSWORD=

ONLYOFFICE_DOCUMENT_SERVER_URL=http://服务器公网IP:8088
ONLYOFFICE_DOCUMENT_SERVER_INTERNAL_URL=http://middleware-onlyoffice
PUBLIC_BACKEND_URL=http://kop-backend:8000
ONLYOFFICE_JWT_SECRET=中间件 OnlyOffice 的 JWT_SECRET

SOFFICE_BIN=/usr/bin/soffice
REBUILD_INDEX_ON_STARTUP=false
```

说明：

- `VITE_API_BASE_URL=` 生产同源部署时留空。
- `CORS_ORIGINS` 填浏览器访问前端的地址，例如 `http://106.53.64.136`。
- `ONLYOFFICE_DOCUMENT_SERVER_URL` 给浏览器访问，所以用公网 IP。
- `ONLYOFFICE_DOCUMENT_SERVER_INTERNAL_URL` 给后端容器访问，所以用容器名。
- `PUBLIC_BACKEND_URL` 给 OnlyOffice 容器回调后端，所以用 `kop-backend:8000`。
- `.env.prod` 里有密钥，不要提交 Git。
- `.env.prod` 不要写 `KEY=value # 注释` 这种行尾注释；Docker Compose 可能会把注释当成值。推荐把注释单独放在上一行。

## 3. 本地生成镜像

如果你想先在本地生成生产镜像，在项目根目录执行：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build
```

这会生成两个镜像：

```text
kop-backend:latest
kop-frontend:latest
```

只构建后端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build backend
```

只构建前端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build frontend
```

查看生成的镜像：

```bash
docker images | grep kop-
```

正常会看到：

```text
kop-backend    latest
kop-frontend   latest
```

如果是在 Windows PowerShell 里查看：

```powershell
docker images | Select-String "kop-"
```

## 4. 本地导出镜像并上传服务器

如果服务器不能直接拉代码构建，可以本地导出镜像：

```bash
docker save kop-backend:latest kop-frontend:latest -o kop-images.tar
```

压缩可选：

```bash
gzip kop-images.tar
```

上传服务器，例如：

```bash
scp kop-images.tar.gz ubuntu@服务器公网IP:/opt/knowledge-orchestration-platform/
```

服务器加载镜像：

```bash
cd /opt/knowledge-orchestration-platform
gunzip kop-images.tar.gz
docker load -i kop-images.tar
```

确认镜像已加载：

```bash
docker images | grep kop-
```

注意：如果使用 `docker load` 加载本地镜像，启动时可以不加 `--build`：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d
```

## 5. 服务器构建并启动

在项目根目录执行：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml config
```

确认 compose 渲染无报错后启动：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

查看服务状态：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml ps
```

查看日志：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f backend
```

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f frontend
```

## 6. 访问地址

如果：

```env
FRONTEND_HTTP_PORT=80
```

浏览器访问：

```text
http://服务器公网IP
```

如果改成：

```env
FRONTEND_HTTP_PORT=8090
```

浏览器访问：

```text
http://服务器公网IP:8090
```

OnlyOffice 默认访问：

```text
http://服务器公网IP:8088
```

## 7. 连通性检查

检查前端：

```bash
curl -I http://服务器公网IP
```

检查后端 API：

```bash
curl http://127.0.0.1:8000/api/health
```

检查 Nginx 代理 API：

```bash
curl http://服务器公网IP/api/health
```

检查 OnlyOffice：

```bash
curl -I http://服务器公网IP:8088/web-apps/apps/api/documents/api.js
```

后端容器访问 MySQL：

```bash
docker exec -it kop-backend python -c "import socket; s=socket.create_connection(('middleware-mysql',3306),5); print('mysql ok'); s.close()"
```

后端容器访问 Redis：

```bash
docker exec -it kop-backend python -c "import socket; s=socket.create_connection(('middleware-redis',6379),5); print('redis ok'); s.close()"
```

后端容器访问 OnlyOffice：

```bash
docker exec -it kop-backend python -c "import urllib.request; r=urllib.request.urlopen('http://middleware-onlyoffice/web-apps/apps/api/documents/api.js', timeout=5); print(r.status)"
```

检查 LibreOffice：

```bash
docker exec -it kop-backend which soffice
```

```bash
docker exec -it kop-backend soffice --version
```

## 8. 数据库初始化

如果 `KOP` 数据库还不存在：

```bash
docker exec -i middleware-mysql mysql -uroot -p你的密码 < sql/KOP_v1_init.sql
```

如果已经有生产数据，不要直接执行初始化脚本，先备份。

检查数据库：

```bash
docker exec -it middleware-mysql mysql -uroot -p你的密码 -e "SHOW DATABASES LIKE 'KOP';"
```

```bash
docker exec -it middleware-mysql mysql -uroot -p你的密码 KOP -e "SHOW TABLES;"
```

## 9. 更新发布

更新全部业务：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

只更新后端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build backend
```

只更新前端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build frontend
```

重启业务服务：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml restart
```

停止业务服务：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml down
```

注意：`down` 只停止业务 compose，不会停止中间件 compose。

## 10. 端口和安全组

公网建议放行：

```text
80
8088
22
```

如果前端不用 80，而用 8090，则放行：

```text
8090
8088
22
```

不建议公网放行：

```text
3306
6379
8000
```

后端 `8000` 当前只绑定服务器本机：

```text
127.0.0.1:8000
```

公网用户通过前端 Nginx 的 `/api` 访问后端。

## 11. 常见问题

### 前端能打开，但接口失败

检查：

```bash
curl http://服务器公网IP/api/health
docker logs -f kop-frontend
docker logs -f kop-backend
```

### 后端连不上 MySQL / Redis

检查容器名和网络：

```bash
docker network inspect shared-middleware_default
```

`kop-backend`、`middleware-mysql`、`middleware-redis` 应该在同一个网络里。

### OnlyOffice 打不开或保存失败

检查：

```bash
curl -I http://服务器公网IP:8088/web-apps/apps/api/documents/api.js
docker exec -it kop-backend python -c "import urllib.request; print(urllib.request.urlopen('http://middleware-onlyoffice/web-apps/apps/api/documents/api.js', timeout=5).status)"
```

确认：

```env
ONLYOFFICE_JWT_SECRET
```

和 `middleware-onlyoffice` 容器里的 `JWT_SECRET` 完全一致。

### 修改了 VITE_API_BASE_URL 但前端没变化

前端环境变量是构建时写入静态文件的，必须重新构建：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build frontend
```

### 后端构建时 Debian apt / LibreOffice 下载中断

如果日志停在 `apt-get install`、`libreoffice-*`、`fonts-noto-cjk`，并出现 `EOF` / `connection reset` / `failed to solve`，通常是 Debian 官方源下载大包不稳定。当前 Dockerfile 已支持通过 `.env.prod` 指定国内源：

```env
APT_MIRROR=http://mirrors.aliyun.com/debian
APT_SECURITY_MIRROR=http://mirrors.aliyun.com/debian-security
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
PIP_TRUSTED_HOST=
```

然后只重建后端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build --no-cache --progress=plain backend
```

如果依然卡在 `fonts-noto-cjk`，可以临时把 Dockerfile 里的 `fonts-noto-cjk` 换成更轻的 `fonts-wqy-zenhei` 和 `fonts-wqy-microhei`，但字体完整度会低一些。
### 后端构建时 PyTorch / torch 默认拉取 CUDA 大包

如果日志里出现大量 `nvidia-*`、`cuda-*`、`triton`，说明 `sentence-transformers` 依赖的 `torch` 默认拉到了 CUDA 版。生产 CPU 服务器不需要这些包，会导致镜像巨大、安装很慢。

当前 Dockerfile 已在安装 `requirements.txt` 前预安装 CPU 版 PyTorch，并用 constraints 锁住：

```env
TORCH_VERSION=2.3.1+cpu
TORCH_INDEX_URL=https://download.pytorch.org/whl/cpu
```

修改后需要重新构建后端：

```bash
docker compose --progress=plain --env-file .env.prod -f docker-compose.prod.yml build --no-cache backend
```
