# 生产部署速查

这份文档只记录上线最常用命令和关键检查点。当前推荐方案是：

```text
已有中间件 compose：MySQL / Redis / ONLYOFFICE / 中间件 Nginx
业务 compose：kop-backend / kop-frontend
```

`kop-frontend` 自带 Nginx，负责托管前端静态文件并把 `/api` 代理到 `kop-backend`。

## 1. 前置条件

服务器上应已经有这些中间件容器：

```bash
docker ps
```

确认存在：

```text
middleware-mysql
middleware-redis
middleware-onlyoffice
```

确认中间件网络存在：

```bash
docker network ls
```

默认网络名：

```text
shared-middleware_default
```

## 2. 生产配置

第一次部署时复制配置：

```bash
cp .env.prod.example .env.prod
```

编辑：

```bash
nano .env.prod
```

最少要确认这些值：

```env
FRONTEND_HTTP_PORT=80
BACKEND_HTTP_PORT=8000
VITE_API_BASE_URL=
MIDDLEWARE_DOCKER_NETWORK=shared-middleware_default

CORS_ORIGINS=http://服务器公网IP

MYSQL_HOST=middleware-mysql
MYSQL_PORT=3306
MYSQL_DATABASE=KOP
MYSQL_USER=root
MYSQL_PASSWORD=服务器真实 MySQL 密码

REDIS_HOST=middleware-redis
REDIS_PORT=6379
REDIS_PASSWORD=

ONLYOFFICE_DOCUMENT_SERVER_URL=http://服务器公网IP:8088
ONLYOFFICE_DOCUMENT_SERVER_INTERNAL_URL=http://middleware-onlyoffice
PUBLIC_BACKEND_URL=http://kop-backend:8000
ONLYOFFICE_JWT_SECRET=中间件 OnlyOffice 的 JWT_SECRET

SOFFICE_BIN=/usr/bin/soffice
REBUILD_INDEX_ON_STARTUP=false
```

说明：

- `VITE_API_BASE_URL=` 生产同源部署时留空。
- `CORS_ORIGINS` 填浏览器访问前端的地址。
- `ONLYOFFICE_DOCUMENT_SERVER_URL` 给浏览器访问，所以用公网 IP。
- `ONLYOFFICE_DOCUMENT_SERVER_INTERNAL_URL` 给后端容器访问，所以用容器名。
- `PUBLIC_BACKEND_URL` 给 OnlyOffice 容器回调后端，所以用 `kop-backend:8000`。
- `.env.prod` 里有密钥，不要提交 Git。
- `.env.prod` 不要写 `KEY=value # 注释` 这种行尾注释；Docker Compose 可能会把注释当成值。推荐把注释单独放在上一行。

## 3. 本地生成镜像

如果你想先在本地生成生产镜像，在项目根目录执行：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build
```

这会生成两个镜像：

```text
kop-backend:latest
kop-frontend:latest
```

只构建后端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build backend
```

只构建前端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build frontend
```

查看生成的镜像：

```bash
docker images | grep kop-
```

正常会看到：

```text
kop-backend    latest
kop-frontend   latest
```

如果是在 Windows PowerShell 里查看：

```powershell
docker images | Select-String "kop-"
```

## 4. 本地导出镜像并上传服务器

如果服务器不直接拉代码构建，推荐本地构建镜像后导出 `.tar`，再上传到服务器加载。

本地导出镜像：

```powershell
docker save kop-backend:latest kop-frontend:latest -o kop-images.tar
```

只导出前端：

```powershell
docker save kop-frontend:latest -o kop-frontend.tar
```

上传到服务器：

```powershell

首次上传前，先在服务器创建部署目录，并把目录权限给 `ubuntu` 用户：

```powershell
ssh -i "C:\Users\30372\.ssh\jackysource2.pem" ubuntu@服务器公网IP "sudo mkdir -p /opt/knowledge-orchestration-platform && sudo chown -R ubuntu:ubuntu /opt/knowledge-orchestration-platform"
```

上传镜像、生产环境配置和业务 compose 文件：

```powershell
scp -i "C:\Users\30372\.ssh\jackysource2.pem" .\kop-images.tar ubuntu@服务器公网IP:/opt/knowledge-orchestration-platform/
scp -i "C:\Users\30372\.ssh\jackysource2.pem" .\.env.prod ubuntu@服务器公网IP:/opt/knowledge-orchestration-platform/.env.prod
scp -i "C:\Users\30372\.ssh\jackysource2.pem" .\docker-compose.prod.yml ubuntu@服务器公网IP:/opt/knowledge-orchestration-platform/docker-compose.prod.yml
scp -i "C:\Users\30372\.ssh\jackysource2.pem" .\sql\KOP_v1_add_index_jobs.sql ubuntu@服务器公网IP:/opt/knowledge-orchestration-platform/KOP_v1_add_index_jobs.sql
```

只上传前端：

```powershell
scp -i "C:\Users\30372\.ssh\jackysource2.pem" .\kop-frontend.tar ubuntu@服务器公网IP:/opt/knowledge-orchestration-platform/kop-frontend.tar
```

服务器加载前端 `.tar` 镜像：

```bash
cd /opt/knowledge-orchestration-platform
docker load -i kop-frontend.tar

服务器加载 `.tar` 镜像：

```bash

docker load -i kop-images.tar

```

确认目录文件：

```bash

```

至少应该有：

```text
.env.prod

kop-images.tar

```

收紧生产环境配置权限：

```bash
chmod 600 .env.prod
```

如果你本地有 `gzip`，也可以选择压缩后上传；Windows PowerShell 默认没有 `gzip`，所以主流程使用 `.tar`：

```bash
gzip kop-images.tar
scp kop-images.tar.gz ubuntu@服务器公网IP:/opt/knowledge-orchestration-platform/

cd /opt/knowledge-orchestration-platform
gunzip kop-images.tar.gz

```

## 5. 服务器启动业务容器

如果服务器已经通过 `docker load` 加载了本地镜像，启动时使用 `--no-build`，避免服务器重新构建。

如果是已有数据库，先执行增量迁移，创建索引任务进度表：

```bash
cd /opt/knowledge-orchestration-platform
docker exec -i middleware-mysql mysql -uroot -p你的MySQL密码 KOP < KOP_v1_add_index_jobs.sql
```

检查任务表是否存在：

```bash
docker exec -it middleware-mysql mysql -uroot -p你的MySQL密码 KOP -e "SHOW TABLES LIKE 'kop_index_job%';"
```

正常应该看到：

```text
kop_index_job
kop_index_job_file
```

先检查 compose 配置。不要直接把完整 `config` 输出粘贴到聊天或文档里，因为里面可能包含环境变量：

```bash
cd /opt/knowledge-orchestration-platform
docker compose --env-file .env.prod -f docker-compose.prod.yml config --quiet
```

没有输出、没有报错就启动：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --no-build
```

只启动前端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --no-build --force-recreate frontend
```

## 9. 更新发布

更新全部业务：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

只更新后端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build backend
```

只更新前端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build frontend
```

重启业务服务：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml restart
```

停止业务服务：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml down
```

注意：`down` 只停止业务 compose，不会停止中间件 compose。

## 11. 常见问题

### 前端能打开，但接口失败

检查：

```bash
curl http://服务器公网IP/api/health
docker logs -f kop-frontend
docker logs -f kop-backend
```

### 后端连不上 MySQL / Redis

检查容器名和网络：

```bash
docker network inspect shared-middleware_default
```

`kop-backend`、`middleware-mysql`、`middleware-redis` 应该在同一个网络里。

### OnlyOffice 打不开或保存失败

检查：

```bash
curl -I http://服务器公网IP:8088/web-apps/apps/api/documents/api.js
docker exec -it kop-backend python -c "import urllib.request; print(urllib.request.urlopen('http://middleware-onlyoffice/web-apps/apps/api/documents/api.js', timeout=5).status)"
```

确认：

```env
ONLYOFFICE_JWT_SECRET
```

和 `middleware-onlyoffice` 容器里的 `JWT_SECRET` 完全一致。

### 修改了 VITE_API_BASE_URL 但前端没变化

前端环境变量是构建时写入静态文件的，必须重新构建：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build frontend
```

### 后端构建时 Debian apt / LibreOffice 下载中断

如果日志停在 `apt-get install`、`libreoffice-*`、`fonts-noto-cjk`，并出现 `EOF` / `connection reset` / `failed to solve`，通常是 Debian 官方源下载大包不稳定。当前 Dockerfile 已支持通过 `.env.prod` 指定国内源：

```env
APT_MIRROR=http://mirrors.aliyun.com/debian
APT_SECURITY_MIRROR=http://mirrors.aliyun.com/debian-security
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
PIP_TRUSTED_HOST=
```

然后只重建后端：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build --no-cache --progress=plain backend
```

如果依然卡在 `fonts-noto-cjk`，可以临时把 Dockerfile 里的 `fonts-noto-cjk` 换成更轻的 `fonts-wqy-zenhei` 和 `fonts-wqy-microhei`，但字体完整度会低一些。
### 后端构建时 PyTorch / torch 默认拉取 CUDA 大包

如果日志里出现大量 `nvidia-*`、`cuda-*`、`triton`，说明 `sentence-transformers` 依赖的 `torch` 默认拉到了 CUDA 版。生产 CPU 服务器不需要这些包，会导致镜像巨大、安装很慢。

当前 Dockerfile 已在安装 `requirements.txt` 前预安装 CPU 版 PyTorch，并用 constraints 锁住：

```env
TORCH_VERSION=2.3.1+cpu
TORCH_INDEX_URL=https://download.pytorch.org/whl/cpu
```

修改后需要重新构建后端：

```bash
docker compose --progress=plain --env-file .env.prod -f docker-compose.prod.yml build --no-cache backend
```

### 上传 / 重建索引时一直等待 Hugging Face 模型下载

后端首次执行文档解析、上传入库或重建索引时，会加载本地 embedding 模型：

```env
EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
```

如果服务器访问 Hugging Face 不稳定，日志里可能会反复出现：

```text
HEAD https://huggingface.co/BAAI/bge-small-zh-v1.5/resolve/main/config.json
Retrying in ...
Network is unreachable
```

当前配置已把模型缓存目录放到 `/app/data` 下，跟随后端 volume 持久化。容器重建后不会重复下载模型：

```env
HF_HOME=data/huggingface
SENTENCE_TRANSFORMERS_HOME=data/sentence-transformers
```

代码使用点：

```text
app/core/settings.py        读取并解析 HF_HOME / SENTENCE_TRANSFORMERS_HOME
app/services/embeddings.py  创建缓存目录，并把 SENTENCE_TRANSFORMERS_HOME 显式传给 SentenceTransformer(cache_folder=...)
```

原因是后端容器工作目录是 `/app`，生产 compose 已挂载：

```yaml
volumes:
  - app_data:/app/data
```

所以实际缓存路径是：

```text
/app/data/huggingface
/app/data/sentence-transformers
```

如果国内服务器访问 `huggingface.co` 很慢，可以在服务器 `.env.prod` 中把主地址临时改成镜像：

```env
HF_ENDPOINT=https://hf-mirror.com
HF_FALLBACK_ENDPOINT=https://huggingface.co
```

修改 `.env.prod` 后重建容器，使环境变量生效：

```bash
cd /opt/knowledge-orchestration-platform
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --force-recreate --no-build backend
```

确认应用解析后的缓存路径：

```bash
docker exec -it kop-backend python -c "from app.core.settings import settings; print('hf_endpoint=', settings.hf_endpoint); print('hf_home=', settings.hf_home); print('sentence_transformers_home=', settings.sentence_transformers_home)"
```

预下载 embedding 模型：

```bash
docker exec -it kop-backend python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-small-zh-v1.5', device='cpu'); print('embedding model ready')"
```

确认缓存已经写入持久卷：

```bash
docker exec -it kop-backend sh -lc "du -sh /app/data/huggingface /app/data/sentence-transformers 2>/dev/null || find /app/data -maxdepth 3 -type d | grep -Ei 'huggingface|sentence'"
```
