# 后续云服务与产品亮点规划

这份文档记录当前域名购买时顺带出现的云服务，以及它们和知识编排平台后续能力之间的关系。

目标不是“看到优惠就都买”，而是判断：

- 哪些现在值得低成本占位
- 哪些以后能真正变成产品亮点
- 哪些只是和当前系统无关的搭售
- 后续如果接入，代码和架构应该怎么演进

---

## 1. 当前购买建议

如果当前页面可选项包括：

- COS 标准存储 100G / 1 年
- 基础图片处理 1TB / 1 年
- 轻量对象存储 10GB / 1 年
- 企业网盘 60GB / 1 个月
- CDN 流量包

建议选择：

| 服务 | 建议 | 原因 |
| --- | --- | --- |
| COS 标准存储 100G / 1 年 | 建议购买 | 和文档库、图片附件、文件备份、对象存储化最匹配 |
| 基础图片处理 1TB / 1 年 | 低价可买 | 如果确实只要 1 元左右，可以作为后续图片压缩、缩略图、水印的试验资源 |
| 轻量对象存储 10GB / 1 年 | 不建议 | 和 COS 定位重叠，容量和流量都偏小，容易造成双存储体系 |
| 企业网盘 60GB / 1 个月 | 不建议 | 是独立网盘产品，不能自然进入当前 RAG / 文档库链路 |
| CDN 流量包 | 暂不建议 | 当前访问量不大，前端和文档下载先走服务器；后续公网访问量上来再买 |

当前最推荐组合：

```text
域名 kopai.work
+ COS 标准存储 100G / 1 年
+ 基础图片处理 1TB / 1 年，仅在价格极低时保留
```

更保守的组合：

```text
域名 kopai.work
+ COS 标准存储 100G / 1 年
```

## 2. 最值得保留的未来亮点

### 2.1 文档资产对象存储化

对应服务：

- COS 标准存储

当前项目的文件主要在服务器本地：

```text
data/user_docs/{user_id}/{folder_id}/...
```

后续可以升级成：

```text
文档上传
├─ 文件写入 COS
├─ MySQL 保存 object_key / size / mime_type / checksum
├─ 索引任务从 COS 下载或流式读取文件
├─ 解析、切片、向量化、写入 Chroma
└─ 前端预览 / 下载时使用临时签名 URL
```

产品亮点可以写成：

- 文档资产云端化存储
- 计算容器和文件存储解耦
- 支持服务器迁移后保留统一文档资产
- 支持后续多服务器部署共享同一份文件
- 支持文档下载、备份、归档和生命周期管理

技术价值：

- 不再把所有文件绑死在单台云服务器磁盘上
- 容器重建、服务器迁移、磁盘扩容时风险更低
- 后续做多实例部署时，后端实例可以共享同一个对象存储

优先级：

```text
高
```

---

### 2.2 图片附件云端化

对应服务：

- COS 标准存储
- 基础图片处理，可选

当前图片输入链路是：

```text
前端粘贴图片
├─ 转成 data:image/...;base64,...
├─ 写入 message_parts
└─ 如果模型支持图片，就直接传给 provider
```

这个方案适合快速验证，但生产上有几个问题：

- base64 很长，消息体膨胀
- 有些 provider 不支持 data URL
- 图片不方便长期保存、复用、预览和审计
- 大图片会增加前端、后端和模型请求压力

后续可以升级成：

```text
前端粘贴图片
├─ 上传到后端
├─ 后端保存到 COS
├─ 可选：基础图片处理生成缩略图 / 压缩版本
├─ 返回 image_url / thumbnail_url
├─ message_parts 保存 image_url
└─ 模型调用时传公网可访问或签名图片 URL
```

产品亮点可以写成：

- 支持图片附件持久化
- 支持图片预览、复用和审计
- 多模态输入不依赖超长 base64
- 支持后续图片压缩、缩略图和水印处理

技术价值：

- 大幅减少聊天消息体积
- 更容易兼容不支持 data URL 的模型供应商
- 图片可以长期挂在聊天记录、知识库引用或 Agent 操作记录里

优先级：

```text
高
```

---

### 2.3 文件预览缓存云端化

对应服务：

- COS 标准存储

当前 Office / PDF 预览可能会在本地生成缓存文件，例如：

```text
data/preview_cache/...
```

后续可以升级成：

```text
Office / 文档预览
├─ LibreOffice 或 ONLYOFFICE 生成 PDF / 预览文件
├─ 后端上传预览缓存到 COS
├─ MySQL 记录 preview_object_key
└─ 前端用签名 URL 打开预览
```

产品亮点可以写成：

- 高保真文档预览缓存
- 文档预览结果可复用，减少重复转换
- 预览文件和原始文件统一纳入云端资产管理

技术价值：

- 减少服务器磁盘压力
- 避免每次打开同一文档都重新转换
- 后续多实例部署时预览缓存不会散落在不同机器

优先级：

```text
中高
```

---

### 2.4 自动备份与迁移能力

对应服务：

- COS 标准存储

当前部署是单机 Docker，核心数据包括：

```text
MySQL
Redis
Chroma
data/user_docs
data/huggingface
data/sentence-transformers
```

后续可以做：

```text
定时备份
├─ MySQL dump
├─ Chroma 数据快照
├─ 用户文档目录
├─ 配置模板
└─ 上传到 COS backup/{date}/...
```

产品亮点可以写成：

- 支持文档和索引数据备份
- 支持服务器迁移和灾备恢复
- 支持按日期保留备份快照

技术价值：

- 降低单机磁盘损坏、误删、迁移失败的风险
- 后续换服务器时，先恢复对象存储和数据库即可

优先级：

```text
中
```

---

### 2.5 CDN 加速

对应服务：

- CDN 流量包

当前阶段不建议购买 CDN，因为：

- 用户量还不大
- 前端静态资源直接由 Nginx 返回即可
- 文档下载和预览流量还没有大到需要 CDN

后续如果系统访问量上来，可以接：

```text
CDN
├─ 前端静态资源加速
├─ 公共下载文件加速
├─ 图片缩略图加速
└─ 文档预览缓存加速
```

产品亮点可以写成：

- 静态资源和文档预览加速
- 大文件下载体验优化
- 图片附件访问加速

注意：

- 私有文档不能直接长期公开 CDN
- 需要配合签名 URL、防盗链、权限校验
- 先上 COS，再考虑 CDN，顺序更稳

优先级：

```text
低到中
```

---

### 2.6 HTTPS 与域名访问

对应服务：

- 域名：`kopai.work`
- SSL 证书
- Nginx 网关

这是当前上线阶段最重要的基础能力。

推荐域名规划：

```text
app.kopai.work       知识库主系统
office.kopai.work    ONLYOFFICE 文档服务
kopai.work           可作为官网或跳转入口
www.kopai.work       可作为官网或跳转入口
```

产品亮点可以写成：

- 独立品牌域名访问
- HTTPS 安全访问
- 前端、后端、ONLYOFFICE 统一由 Nginx 网关管理
- 外部访问 HTTPS，容器内部保留 HTTP，部署更清晰

优先级：

```text
最高
```

## 3. 不建议购买或暂不接入的服务

### 3.1 轻量对象存储

不建议现在买。

原因：

- 和 COS 标准存储定位重叠
- 10GB 容量偏小
- 外网流量通常也偏小
- 后续代码如果同时支持 COS 和轻量对象存储，会增加无必要复杂度

建议：

```text
统一走 COS 标准存储。
```

---

### 3.2 企业网盘

不建议现在买。

原因：

- 它是给人直接使用的独立网盘
- 当前系统已经有自己的文档库、文件夹、上传、预览、在线编辑、索引和检索
- 企业网盘不会自动进入 RAG 链路
- 只有 1 个月套餐，后续续费价值不高

除非后面明确要做：

```text
企业网盘文件同步到知识库
```

否则现在不需要。

## 4. 推荐落地阶段

### 第一阶段：域名 + HTTPS

目标：

```text
https://app.kopai.work
https://office.kopai.work
```

要做：

- DNS A 记录解析到服务器
- Nginx 接管公网 80 / 443
- 配置 SSL 证书
- `.env.prod` 改成域名地址
- ONLYOFFICE 文档服务也用 HTTPS 域名

价值：

- 正式可访问
- 避免 HTTPS 页面加载 HTTP ONLYOFFICE 被浏览器拦截
- 对外展示更专业

---

### 第二阶段：COS 文档资产存储

目标：

```text
用户上传文件可以落到 COS
```

建议新增配置：

```env
STORAGE_BACKEND=local
COS_SECRET_ID=
COS_SECRET_KEY=
COS_REGION=
COS_BUCKET=
COS_APP_ID=
COS_PUBLIC_BASE_URL=
COS_SIGNED_URL_TTL_SEC=600
```

建议新增数据库字段：

```text
kop_document_file
├─ storage_backend: local / cos
├─ storage_key
├─ storage_bucket
├─ storage_region
├─ checksum
├─ preview_storage_key
└─ thumbnail_storage_key
```

迁移策略：

```text
先保留 local
再新增 cos
最后做可选迁移脚本
```

不要一开始就删掉本地存储逻辑。

---

### 第三阶段：图片附件云端化

目标：

```text
粘贴图片不再直接长期依赖 base64
```

链路：

```text
ChatComposer.vue
├─ paste 图片
├─ 调 upload image API
├─ 后端写 COS
├─ 返回 image_url / thumbnail_url
└─ message_parts 保存 URL
```

后端新增接口可以是：

```text
POST /api/chat/assets/images
```

返回：

```json
{
  "asset_id": 1,
  "image_url": "https://...",
  "thumbnail_url": "https://...",
  "mime_type": "image/png",
  "size": 123456
}
```

---

### 第四阶段：预览缓存与备份上云

目标：

```text
预览文件和备份文件不再只放服务器磁盘
```

可做：

- Office 转 PDF 后上传 COS
- 文档预览缩略图上传 COS
- MySQL dump 定期上传 COS
- Chroma 快照定期上传 COS
- 用户文档本地副本定期同步 COS

---

### 第五阶段：CDN 加速

触发条件：

- 前端访问用户变多
- 文档下载流量明显增加
- 图片附件访问慢
- 对公网体验有要求

再考虑 CDN。

当前阶段不用急。

---

## 5. 可以写到登录页或项目介绍里的亮点文案

如果后续完成 COS / 图片资产 / HTTPS，可以这样写。

### 简洁版

```text
云端文档资产
```

```text
多模态知识输入
```

```text
生产级访问入口
```

```text
对象存储解耦
```

```text
图片资产管线

```

```text
统一公网网关
Nginx 接管 80/443，按域名转发前端、后端 API 和 ONLYOFFICE，容器内部保持轻量 HTTP。
```

## 6. 当前最终建议

现在购买：

```text
必须买：
- kopai.work 域名

建议买：
- COS 标准存储 100G / 1 年

可选买：
- 基础图片处理 1TB / 1 年，如果确实只要 1 元左右

不要买：
- 轻量对象存储 10GB
- 企业网盘 60GB
- CDN 流量包，当前阶段先不买
```

后续落地优先级：

```text
1. 域名 + HTTPS
2. Nginx 统一网关
3. COS 文档资产存储
4. 图片附件云端化
5. 预览缓存和备份上云
6. 访问量上来后再接 CDN
```

一句话判断：

```text
COS 是未来真正能进入系统架构的亮点；
基础图片处理是低价可选增强；
企业网盘和轻量对象存储更像搭售，不适合当前系统主线。
```
